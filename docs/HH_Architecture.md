# BridgeUs 橋得攏 — Human-Human 對話系統架構

## 一、架構總覽

H-H 對話系統的核心原則：**全程不呼叫 LLM（僅對話結束後的摘要生成例外）**。即時處理完全依賴 Sentence-Transformers + 規則式邏輯，確保低延遲與低成本。

系統分為五層：WebSocket 對話通道、NLP 即時監控、階段性分析、對話結束處理、資料儲存。

---

## 二、實驗設計框架

### 對話結構

採用 **雙 Session 制**，每次 Session 60 分鐘，兩次間隔 1–3 天：

| 項目 | Session 1 | 間隔期 | Session 2 |
|------|-----------|--------|-----------|
| 時長 | 60 分鐘 | 1–3 天 | 60 分鐘 |
| 階段定位 | 探索 + 交鋒 | 反芻（自我說服） | 收斂 + 總結 |
| 系統動作 | 即時監控 + CCND 生成 | 開放 CCND 回顧 + 對話摘要 | 即時監控 + CCND 更新 |
| 問卷 | Session 前：前測問卷 | 無 | Session 後：後測問卷 |
| 數據產出 | 中期 CCND 快照、立場分數 | 間隔期立場自評（可選） | 最終 CCND、量化報告 |

### 結束條件

- 任一方主動結束對話
- 達到 60 分鐘時間上限
- 雙方連續 3 分鐘無發言（系統提示後仍無回應則自動結束）

## 三、系統五層架構

### 第一層：WebSocket 對話通道

**技術：** Django Channels（ASGI）

**訊息路由邏輯：**

```
用戶 A 發送訊息
    ↓
Django Channels Consumer 接收
    ↓
    ├──→ 即時轉發給用戶 B（低延遲路徑）
    │
    └──→ 丟入 NLP Pipeline（非同步路徑）
              ├── 情緒偵測
              ├── 攻擊性過濾
              ├── 離題偵測
              └── CCND 更新
```

**關鍵設計：**
- 訊息經後端中轉（非 P2P），系統才能攔截分析
- 轉發與 NLP 分析並行，轉發不等待分析結果
- 例外：攻擊性過濾為同步檢查，觸發時阻擋該訊息轉發

### 第二層：NLP 即時監控 Pipeline

每則訊息觸發，全部使用規則式 + Sentence-Transformers，不呼叫 LLM。

#### 2.1 情緒強度偵測

- **模型：** 輕量情緒分類模型（如 HuggingFace 中文情緒分類）或 Sentence-Transformers 情緒向量
- **閾值：** 情緒分數 > 設定閾值
- **觸發動作：** 對發言者彈出系統提示（預寫訊息庫隨機選取）
- **提示範例：**
  - 「請試著用更平和的方式表達你的觀點」
  - 「深呼吸一下，試著聚焦在論點本身」
- **數據記錄：** 每則訊息的情緒分數存入 PostgreSQL

#### 2.2 攻擊性詞彙過濾

- **機制：** 關鍵字黑名單 + 輕量分類器（二階段）
- **第一階段：** 關鍵字命中 → 直接攔截（同步，< 50ms）
- **第二階段：** 分類器判斷（非同步，分類器信心度 > 閾值 → 追溯攔截）
- **觸發動作：** 不轉發該訊息，要求發言者重新表達
- **注意：** 此為唯一同步阻擋機制，其餘監控皆為非同步

#### 2.3 離題偵測

- **機制：** 當前發言 embedding vs 議題錨點 embedding（問卷階段產生的議題向量）
- **計算：** 餘弦相似度，低於閾值 → 判定離題
- **觸發動作：** 彈出系統提示引導回到議題
- **提示範例：** 「目前的討論似乎偏離了主題，可以試著回到 [議題名稱] 的討論」

#### 2.4 CCND 節點生成與更新

- **模型：** `paraphrase-multilingual-MiniLM-L12-v2`（768 維，支援中文）
- **流程：** 每則發言 → 算 embedding → 存入 pgvector → 計算與既有節點的語義距離 → 透過 WebSocket 推送前端 D3.js 更新力導向圖
- **延遲：** 約 1–2 秒
- **前端呈現：** 每個節點代表一則觀點，節點間距離 = 語義距離，力導向圖自動佈局

### 第三層：階段性分析（累積觸發）

非逐則觸發，而是滿足以下條件時執行：

#### 3.1 立場漂移追蹤

- **觸發條件：** 每累積 200 字 或 每 15 分鐘（取先到者）
- **計算方式：** 該區間所有發言的平均 embedding vs 用戶初始立場向量（問卷產生）
- **產出：** drift 值（餘弦距離），存入資料庫
- **用途：** 追蹤用戶立場隨時間的漂移軌跡

#### 3.2 僵局偵測

- **觸發條件：** 連續 4–5 輪雙方語義距離變化量 < 閾值
- **判定邏輯：** 雙方各自的觀點向量在最近 N 輪中沒有顯著移動
- **觸發動作：** 彈出系統提示，內容從對方近期發言中用 NLP 抽取關鍵詞填入
- **提示範例：** 「對方剛才提到了關於 [關鍵詞] 的看法，你怎麼看這個觀點？」

#### 3.3 對話階段自動標記

- **三階段：** 探索期 → 交鋒期 → 收斂期
- **標記依據：**
  - 探索期：對話前期，雙方語義距離在擴大或維持高距離
  - 交鋒期：雙方開始針對同一子議題來回論述，語義距離出現波動
  - 收斂期：語義距離持續縮小，或雙方出現共識性用語
- **用途：** 僅供後續研究分析使用，不對用戶顯示
- **儲存：** 每次標記變更記錄時間戳存入 PostgreSQL

### 第四層：對話結束處理

#### 4.1 Session 1 結束時

- 推送中期回顧問卷（可選，簡短 3–5 題）
- 生成 Session 1 對話摘要（此處呼叫 LLM，非即時需求）
- 儲存 CCND 中期快照（D3.js 圖的節點座標 + 連線關係 JSON）
- 記錄 Session 1 最終立場漂移值

#### 4.2 間隔期（1–3 天）

- 用戶可登入平台查看：
  - 自己的 CCND 圖（唯讀）
  - Session 1 對話摘要（LLM 生成）
- 不可繼續對話
- 此設計基於 Aronson (1999) 自我說服理論：給用戶內化反芻的時間

#### 4.3 Session 2 結束時

- 推送後測問卷（完整版，與前測問卷對應）
- 生成完整對話摘要（跨兩次 Session）
- 儲存最終版 CCND 快照
- 自動產出量化報告：
  - 情緒分數變化曲線（Session 1 + Session 2）
  - 立場漂移軌跡圖
  - CCND 拓撲結構變化（Session 1 快照 vs Session 2 快照）
  - 對話統計（發言次數、平均字數、回應時間）

### 第五層：資料儲存

#### PostgreSQL（結構化數據）

| 資料表 | 內容 | 說明 |
|--------|------|------|
| `users` | 帳戶資訊 | 基本身份驗證 |
| `questionnaires` | 前測/後測問卷結果 | 李克特量表分數 + 開放式回答 |
| `conversations` | 對話 metadata | 配對雙方 ID、議題、開始/結束時間、Session 編號 |
| `messages` | 逐則訊息 | 發言者 ID、時間戳、原始文字、情緒分數、階段標記 |
| `stance_drift` | 立場漂移紀錄 | 用戶 ID、時間點、drift 值 |
| `ccnd_snapshots` | CCND 快照 | JSON 格式，記錄節點座標與連線關係 |
| `analysis_reports` | 量化報告 | Session 結束後生成 |

#### pgvector（向量數據）

| 用途 | 維度 | 模型 |
|------|------|------|
| 每則發言 embedding | 768 | `paraphrase-multilingual-MiniLM-L12-v2` |
| 用戶初始立場向量 | 768 | 同上（問卷開放式回答的 embedding） |
| 議題錨點向量 | 768 | 同上（議題描述文本的 embedding） |

#### 不使用 ChromaDB

H-H 模式無 RAG 需求，所有向量儲存統一使用 pgvector，避免維護兩套向量資料庫。

## 四、系統提示訊息庫

所有系統介入皆為預寫訊息，不經 LLM 生成，確保一致性與即時性。

### 分類

| 類別 | 觸發條件 | 訊息範例 |
|------|----------|---------|
| 情緒緩和 | 情緒分數超標 | 「請試著用更平和的方式表達」 |
| 攻擊攔截 | 攻擊性詞彙命中 | 「這則訊息包含可能冒犯對方的用語，請修改後重新發送」 |
| 離題提醒 | 語義距離偏離議題錨點 | 「目前討論似乎偏離了主題，可以回到 [議題] 的討論」 |
| 僵局打破 | 連續 N 輪語義距離無變化 | 「對方提到了 [關鍵詞]，你怎麼看？」 |
| 時間提醒 | 剩餘 10 分鐘 / 5 分鐘 | 「本次對話剩餘 10 分鐘」 |
| 沉默提示 | 單方 2 分鐘未發言 | 「對方正在等待你的回應」 |

## 五、與 H-AI 共用模組

以下模組在 H-H 和 H-AI 模式中共用，開發時需統一介面：

| 模組 | H-H 使用方式 | H-AI 使用方式 |
|------|-------------|-------------|
| 問卷系統 | 前/後測問卷 | 前/後測問卷 |
| 配對演算法 | 配對真人 | 不需配對，直接生成 AI 對手 |
| CCND 視覺化 | 雙方皆為真人節點 | 一方為用戶節點，一方為 AI 節點 |
| pgvector 儲存 | 發言 embedding | 發言 embedding（含 AI 回應） |
| 量化報告生成 | 雙方分析 | 僅分析用戶端 |
| 對話摘要（LLM） | 結束後生成 | 結束後生成 |
| 情緒偵測 | 雙方皆監控 | 僅監控用戶端 |
| 離題偵測 | 雙方皆監控 | 僅監控用戶端（AI 不會離題） |
